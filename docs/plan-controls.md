# 计划版本中的追价与完整费用规则

这两个选项位于现有“标的与计划”页，与支撑、止损和入场区间一起保存到不可变 `plan_versions`。没有新增工作页、真实交易接口或生产行情适配器。生产能力仍默认关闭。

## 追价上限

`PlanInput.chaseLimit` 显式保存 `enabled`。开启时 `maxPercent` 是用户填写的百分数十进制字符串，例如填写 `3` 表示 3%，不是 300%。页面不预填这一数字；关闭时不向状态机传递追价门。旧版本没有该对象时保持原来的关闭行为。

统一的 `chaseRatio` 使用隔离的64位十进制上下文转换百分数，不经过 JavaScript 浮点数或全局 Decimal 精度。快速演示、持久合成运行器、正式闭合运行器和恢复尝试都从对应不可变计划版本读取。恢复到一个明确关闭的新版本会删除旧尝试的开启值。

既有纯状态机保持原公式：`(Echeck - LOD_known) / LOD_known`，严格超过上限阻断，等号通过。LOD 必须来自当前常规会话、在决策时已知的完整覆盖；报价不会补足缺失分钟，恢复后局部低点不会冒充全会话低点。技术突破仍只消费一次；追价失败保存技术事件与阻断事件，不在后来价格变动后重发。旧事件的低点、覆盖截止、配置、计划和输入哈希保持不变。

## 本计划完整费用规则

`PlanInput.feeSchedule` 复用风险纯核已有的 `FeeSchedule`。页面要求用户填写：

- USD 或 CNY 报价币种；必须匹配证券币种才能通过风险。
- 用户核对的规则版本和生效日期。
- 买入、卖出两侧各自的最低费用、固定费用、每股费用与成交额费率。
- 当前完整版本的明确确认；修改任何费用字段会取消确认。

所有数值初始为空，无该项费用须明确填0。成交额费率是小数比例，例如0.1%填写0.001，仅为单位说明。没有预选券商、推荐费率或个人风险比例。保存未确认或币种不符的完整研究估算是允许的，但风险、预留和启用均阻断；缺少分量、非法日期、负数、未知字段不被静默补零或丢弃。

费用公式保持原纯核实现：每侧 `max(minimum, fixed + perShare*q + notionalRate*q*price)`，向上取整到0.01报价货币单位；数量为0时费用为0。买入使用核算入场价，卖出使用保守止损执行价。数量变化时重新计算完整费用，不把每笔最低费用乘以股数。

计划预留、资金刷新重建、快速/持久演示和正式实时钟风险复核都传入相同的计划费用表。完整费用确认由该计划版本自己承担，资金设置里的旧费用确认只控制旧固定费用模式。资金变化仍需新的账户快照代际；行情触发数量不得超过此前批准数量和当前正式预留数量。事件显示实际费用、规则版本和币种，只读审计使用冻结计划费用表重新求解，不读取当前设置替代原值。

## 旧版本兼容

旧计划没有 `feeSchedule` 时继续使用已存在的 `Funds.buyFee` / `sellFee` 与 `feesConfirmed`，算法标识仍为 `manual-fixed-minimum-v1`。不会凭空构造券商规则、币种版本或改写旧计划。页面明确标为旧版固定费用；用户填写完整规则并保存新计划版本后才采用完整费表。

旧事件保留其原始冻结资金、固定费用和输入哈希；后续费用设置或计划更新不改变旧结果。新完整费表冻结在计划版本中，后续资金设置变更不会替换它。计划更新仍使用现有计划版本与尝试双CAS；旧标签页冲突保留草稿并展示费用和追价字段差异。

## 验证范围

新增服务端样本覆盖追价3%等号、3.01%阻断、断线恢复缺低点、后来低点不回写、演示与正式尝试的同版本配置、完整费用组合、最低费、缩量后重算、币种/确认阻断、CAS及旧事件审计。浏览器样本覆盖桌面与390px的完整表单、刷新、版本编辑、双标签冲突、实际费用与历史证据。

所有市场输入均为标注的合成/隔离契约夹具。真实券商费率、行情授权、生产适配器和目标主机验收仍未完成；用户确认估算不代表系统独立核验过券商收费或保证最大损失。
