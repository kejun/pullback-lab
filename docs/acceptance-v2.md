## 验证说明

验证命令：`npm run typecheck`、`npm test`、`npm run build`、`npm run test:e2e`。浏览器测试使用独立临时文件数据库，也经过实际服务锁和迁移。当前环境使用 Chromium 153.0.8010.0 与 Noto Sans CJK SC；CI 使用 Playwright 配套浏览器。

最终本地结果：严格类型检查和生产构建通过；13 个文件、154 项单元及集成测试通过；2 项浏览器测试通过。浏览器覆盖支撑家族失效及恢复、计划版本冲突、只读回放、实际价量偏离、反馈多标签页冲突后显式重读和第三次修订，以及资金过期保护。远端 CI 以 PR 当前提交的检查结果为准。

回放检查覆盖完整的旧版本 v1 冻结结构，不因加入新的支撑快照而虚构触发算法版本变化。未知算法或缺少结构返回 UNSUPPORTED；篡改、乱序、冲突重复或输出不同返回 MISMATCH。MATCH 的风险覆盖范围明确区分最终风险独立重算和早期冻结风险门结论。

故障注入使用真实 SQLite 连接和子进程：第二服务在恢复前拒绝；锁正常释放和 SIGKILL 释放；历史数据迁移失败整体回滚；事实更新、删除、替换拒绝；竞争写入返回 SQLITE_BUSY；`max_page_count` 触发真实 SQLITE_FULL；通知写入前和完整提交后分别 SIGKILL，重开数据库后事件与通知均保持全有或全无，重新回放不重复发布。页数限制不是宿主文件系统 ENOSPC，SIGKILL 也不能替代主机断电演练。

## 性能基线

执行 `npm run benchmark`，默认 30 轮。脚本创建并清理临时文件数据库，装入 100 个合成标的、每个 300 根日线，始终同时启用 10 个合成计划。候选请求通过真实鉴权与 HTTP 处理器；回放计时包含事务提交；审计读取归档并验证零写入。

数值报告以脚本输出的运行环境和测量范围为准。冷请求表示修改元数据后的请求，热请求表示重复请求；没有宣称清空操作系统页缓存或实现候选结果缓存。所有调用均在本机，无供应商请求、网络传输和真实可操作信号延迟；上游失败应独立计数，不能记成快速成功。

2026-10-12 文件数据库基线见 [benchmark-v2.json](benchmark-v2.json)：Node 24.19.0、SQLite 3.53.4、WAL、synchronous=FULL、容器 overlayfs。累计 300 个归档尝试的审计全部 MATCH，审计期间数据库零写入。

| 测量项                         |         P95 |
| ------------------------------ | ----------: |
| 100 标的候选，元数据修改后请求 | 1320.578 ms |
| 100 标的候选，连续重复请求     | 1311.668 ms |
| 10 个合成计划回放及入库        |  225.786 ms |
| 10 条归档输入只读审计          |  162.588 ms |

以上包含配置的 SQLite 同步调用，未证明物理断电耐久性，也不能代替目标主机磁盘基准。按事件 ID 和尝试 ID 精确读取历史，避免每次回放解析全库冻结快照；未为当前已达标的候选查询额外增加缓存。
