# 本机非破坏性验收

`npm run acceptance:local` 针对已经启动的单用户 npm 部署收集目标机器证据。它不重启服务、不修改原数据库业务数据、不读取密码或 Longbridge 凭据，也不访问供应商或上传任何文件。用户已确认页面可打开时，不要求额外截图。

## 一次运行

先使用同一个已通过 CI 的代码版本执行 `npm ci` 和 `npm run build`，按既有方式启动应用。在第二个终端进入同一仓库根目录，再运行：

```bash
mkdir -p private
npm run acceptance:local -- \
  --database "$HOME/Library/Application Support/Pullback Lab/pullback.sqlite" \
  --url http://127.0.0.1:3000 \
  --output-dir "private/local-acceptance-$(date -u +%Y%m%dT%H%M%SZ)" \
  --summary
```

把 `--database` 改成实际运行服务的 `PULLBACK_DB`。上面的路径仅对应使用该路径安装的 Mac；仓库默认路径是 `data/pullback.sqlite`。指定 `--database` 优先于当前终端的 `PULLBACK_DB`；两者都没有时使用默认路径。端口不为 3000 时修改 `--url`。

输出目录必须尚不存在，父目录必须已经存在。目录采用 0700 权限，报告、备份与恢复数据库采用 0600。请保证有足够空间容纳两份数据库副本及临时文件，不要把数据库或输出目录放在网络盘。程序不自动删除旧结果，也不覆盖既有文件。

允许的目标仅为 `127.0.0.1` 或 `[::1]` 的 HTTP/HTTPS 来源，不接受域名、用户名、密码、查询参数或路径。请求使用直连 socket，不使用代理环境，不跟随重定向；HTTPS 仍需通过正常证书校验。对外域名、VPN、隧道及公网代理不在此命令验证范围。不要为通过检查而关闭 TLS 验证或更改安全设置。

`--summary` 在终端输出简短 JSON，包含实际 CLI 提交与工作区状态、操作系统/CPU 架构/Node/SQLite 版本、检查数量、失败项、样本覆盖情况和未验收项数量。不加该参数则输出完整脱敏报告。退出码 0 仅表示本次自动检查没有失败或未运行项；无样本的项目仍为 `NOT_APPLICABLE`，不代表整体验收通过。

## 生成的文件与隐私

新目录包含：

- `report.json`：完整脱敏报告，可由用户检查后分享。
- `backup.sqlite`：原库的一致快照，含资金、标的、笔记、历史及认证摘要，只留在用户本地。
- `restored.sqlite`：从快照创建的独立恢复副本，同样属于私有数据。
- 可能存在已释放的 SQLite 进程锁侧车文件；不能靠删除正在使用的锁文件处理服务占用。

只分享短摘要或 `report.json`，不要上传整个目录。报告不包含路径、用户名、标的、资金金额、笔记、认证摘要、环境变量、原始异常、HTTP 响应内容或私有记录的指纹。运行的子进程移除 `PULLBACK_PASSWORD` 和全部 `LONGBRIDGE_*` 环境变量。备份与恢复副本不是脱敏报告。

## 自动验证范围

1. 读取 CLI 所在 checkout 的提交号和是否干净。正在运行的服务可能仍使用旧代码或另一个数据库，因此 `runningServerCommit` 永远标为 `UNVERIFIED`，不能用 CLI 提交号冒充服务提交。
2. 以 SQLite 只读连接核验实际加载的运行库、当前 schema 和文件条件，不在原库创建 `Store`、运行迁移或触发恢复。旧 schema 拒绝验收，应先按升级流程备份并正常启动新应用。SQLite 只读访问可能参与 WAL/SHM 协调，不承诺侧车文件字节不变。
3. 复用 `backupDatabase` 的在线一致快照、完整性、外键和应用结构检查，包含已提交 WAL，排除未提交事务。
4. 从该固定快照恢复到新文件；迁移及状态失效只发生在恢复副本。逐表比较历史与证据、预留，检查旧资金版本保留且当前资金变为 STALE、未完成计划暂停、旧会话和幂等结果清除、提醒游标轮转。私有行指纹仅在内存比较，不进入报告。
5. 对目标 loopback 服务执行匿名 GET：健康接口、研究 API、运维 API、SSE 和编码路径 API。私有接口必须返回 401；重定向、未配置密码导致的 503、连接失败或格式错误都不能算通过。

每个 HTTP 请求总时限为 2.5 秒，响应体最多 4 KiB；整个 CLI 使用独立父进程设置 120 秒上限。超时或中断会结束检查，原库不执行业务写入，新目录可能保留不完整的私有副本。不要把超时当成通过，也不要覆盖同名结果重跑，应使用另一个新目录并排查原因。

如果原库没有资金、会话、未完成计划、预留或命令结果，对应恢复检查标为 `NOT_APPLICABLE`。`coverage` 明确记录是否存在相关真实样本；空表一致不能代替有样本的恢复验收。程序不为凑齐覆盖向实际部署写入演示数据。

## 仍需实际验证的项目

报告始终保留 `releaseStatus: NOT_ACCEPTED`。下面的检查不能由一次只读诊断替代，也不能把合成 CI 证据当成真实目标机器已通过：

- 核对运行服务的实际提交、数据库和本地磁盘归属；诊断的 Node/SQLite 是 CLI 加载的运行库，不是远端进程证明。
- 登录后的 Cookie、Origin/CSRF 与真实浏览器 SSE 重连、游标失效恢复。
- 关闭浏览器后后台仍工作；受用户控制的进程停止/守护重启、主机重启后持久记录读回。
- 主机休眠、断网、VPN 变化后的及时暂停和显式恢复；时钟同步。
- 把一致备份保存到独立私有介质，再恢复到另一个全新文件后的实际读回。同盘两个副本不能证明异地恢复。
- 宿主满盘、突然断电及持久介质耐久性。这些具有风险，命令不会自动制造故障。
- 若对外提供访问：真实域名/TLS、代理链和 SSE 长连接。
- 逐市场真实 OpenAPI 权限、地区、单位、日历、收盘语义、公司行动及连续性，以及真实端到端延迟与上游延迟。

恢复副本只是验收材料，命令不会让实际服务切换到该文件。实际恢复仍按 [运维恢复顺序](operations.md#恢复顺序)执行并重新确认资金与计划。正式链合成性能报告与本机运行报告应分开归档。
