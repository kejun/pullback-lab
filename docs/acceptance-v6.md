## 实现与原问题

| 范围 | 原问题 | 本批行为 |
| --- | --- | --- |
| 已交易占用 | 记录 TAKEN 后，计划编辑或暂停仍能将 TAKEN_PENDING 写成 RELEASED | 普通释放只处理 ACTIVE；TAKEN_PENDING 仅由用户确认新资金快照后吸收。编辑仍可保存新草稿，但待核对资金阻断风险通过与启用 |
| 控制命令 | 仅核对 plan.version，旧标签页可能操作同版本的新 attempt | 保存版本、启用、暂停和快速回放同时核对 expectedAttemptId；校验与写入共用即时事务。省略尝试字段返回 400，旧尝试返回 409，成功命令重试只读回原结果 |
| 恢复身份 | 新启用的分步运行仍从开盘开始，继承昨收高于 U 的会话首次身份 | 增加显式 RECOVERY，引用最新同证券同会话的旧运行水位，创建新 attempt 和证据代际，仅处理水位之后完整的新行情 |
| 恢复条件 | 旧回踩、旧参考和迟到输入可能被重新使用 | 新状态不继承 aboveEvidence、参考、触发或已处理输入；须先观察完整新 K 线收盘高于 U，再等待新回踩；已消费尝试、缺水位、旧步数和首小时结束均拒绝 |
| 版本与历史 | 保存新版本清空当前 attempt，恢复来源不再可见 | GET runtime 可返回同计划同会话最近旧来源；显式恢复使用新版本参数和支撑快照，保留旧输入、状态、事件和原始合成序列 |
| 资金重建 | 恢复若重建占用可能改变排队顺序或覆盖待核对交易 | 恢复保持原批准数量上限和 allocationOrder；失败整体回滚。新资金先保留已提醒待反馈占用，再稳定重建其余计划 |
| 浏览器 | 版本号相同却换了尝试时不易发现，刷新可能悄然替换草稿基线 | 409 显示旧、新尝试身份并保留草稿；用户明确采用最新基线后才能保存；恢复入口展示来源、水位和身份 |

纯函数触发算法版本保持 v1，恢复归档继续可只读重放。恢复后的局部日内低点明确标为不完整，不以新尝试的部分输入宣称已覆盖全会话。新版本的背景确认、关注理由、筛选确认、日线完整性及支撑证据必须重新通过启用检查。

## 验收映射

- T08/T16、U06/U08/U09：恢复第一根已在支撑区不 ARMED；新收盘高于 U 后再回踩才确认；旧水位前输入拒绝；跨版本沿用旧水位而不重放旧判断；全部旧档案保持原字节。
- T22、U05/U10/U13/U14：TAKEN 后编辑/暂停/过期均不释放待核对占用；更正旧反馈不影响新 attempt 预留；资金重建先保护待反馈，再按稳定顺序缩量或暂停；失败全部回滚。
- 命令与事务：同版本旧 attempt 的保存、启用、暂停、回放拒绝；相同幂等键重试返回原结果；恢复创建、资金替换与新检查点写入必须全有或全无。
- 浏览器：双标签同版本尝试冲突、草稿保留、显式采用新基线、跨版本恢复与最新表单字段一致性；恢复测试使用独立服务及数据库，避免其他场景的资金占用污染。
