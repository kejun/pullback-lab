# 正式运行链离线性能验收（KEJ-59）

本报告补齐正式接收运行链的性能证据。此前 `benchmark-v4.json` 测量的是 `replayPlan` 历史回放，不能证明正式输入到 `ENTRY_TRIGGERED` 的性能；旧报告保留其原有范围。

## 可重复命令与源码

```bash
npm ci
npm run --silent benchmark:formal -- --rounds=30 > formal-benchmark-report.json
```

默认 30 轮，允许 `--rounds=1` 至 `--rounds=100`。除正式合格输入、整批处理和缓存命中的阈值外，任一失败、缺失样本、归档审计失败或清理失败都会使报告 `FAIL`，并退出 1。无效参数或无法初始化也输出可解析的失败 JSON 并退出 1。执行环境若强制终止进程而未得到完整报告，只能记为未完成，不能宣称通过。

保存报告到仓库外可避免下次运行将该未跟踪文件记为源码变化。临时数据库位于当前 checkout 文件系统，每轮一个独立文件；关闭独立读连接与应用后清理整个临时目录。脚本从未导入生产启动入口。

## 环境与计时边界

- Node.js 24.19.0，SQLite 3.53.4，Linux 6.18.44；AMD EPYC 9V74，进程可用并行度 9。
- 真实文件 SQLite，验证 `journal_mode=WAL`、`synchronous=FULL`；独立只读连接检查提交可见性。
- 文件系统类型 `0x794c7630`，即 Linux overlay。初步试跑发现 `/tmp` 是 tmpfs 后，正式报告改在 checkout 文件系统重新执行；本文和 JSON 数值均来自该次 overlay 运行，不使用 tmpfs 初步结果。
- 云宿主没有做性能隔离。此配置包含 SQLite 同步调用，但不能证明物理磁盘持久性，也不能代表用户目标主机的磁盘性能。
- 使用单调 `performance.now()` 计时。可注入服务器时钟仅生成固定开盘后两分钟的业务事实，不用业务时间差冒充计算延迟。
- 候选页面范围是经过鉴权的 `Fastify.inject` 后端 API、JSON 序列化及读回；不含 socket、网络或浏览器渲染。每轮新应用先测缓存未命中，再立即测缓存命中，并核对 `cacheHit`、100 条候选及100条完整覆盖。

正式输入计时从调用已合格闭合分钟的适配器 sink 之前开始，包含：不可变接收回执入库、生产运行器的自动 drain、标准化/完整性与参考判断、当前风险重算、状态/预留/ENTRY/通知事务、WAL/FULL 提交，以及独立连接读回。读回在一个只读快照内核对：

1. 恰好一条非历史 `ENTRY_TRIGGERED`，`closed-bar-v1` 输入快照及其哈希。
2. 关联的合格分钟内容/哈希和 `ACCEPTED` 回执处理结果。
3. 已消费的尝试、`TRIGGERED` 计划与运行状态、对应水位。
4. 相同尝试的有效资金预留及事件数量。
5. 通知、事件摘要和 SSE 持久事件各存在一次。

10 个监测在同一轮同时活动；在同一 JavaScript turn 依次提交 10 个合格输入。每条从自己的回调入口计时，另外记录第一条入口到最后一条独立读回的整批耗时，保守覆盖批内排队。没有把串行耗时宣传为多线程吞吐或进程竞争测试。

登录、完整历史准备、计划创建/正式激活、触碰分钟、必要的新鲜报价、计时后的只读归档审计与关闭均不纳入输入计时。每轮使用新库和新应用，但不会清空 OS 或 JIT 缓存；只测固定首次机会，不代表长会话、不断增长的归档或全部边界路径。

## 失败与测试证据

最近秩 P95 只对成功样本定义；报告同时逐条保留失败耗时/错误码，以及计划、尝试、成功、失败、未尝试数量。任何失败或未尝试都令该目标失败，即使成功样本 P95 很低。不能用删除失败样本获得通过。

新增 [formal-benchmark.test.ts](../tests/formal-benchmark.test.ts) 的四项回归覆盖：

- 100 个完整历史、10 个正式监测、10 条事务提交独立读回与归档 `MATCH`。
- 在回执处置事务注入真实 SQLite `RAISE(ABORT)`：失败样本保留，整批和总体结果均失败；后续样本仍统计，清理完成。
- 最近秩计算、阈值等号、缺失样本和零成功样本不能通过。
- 独立 CLI 进程的非法参数非零退出、可解析 JSON 和不回显参数值。

这不是替换既有 T01–T25/U01–U14 验收：原映射见 [首批映射](acceptance.md#验收映射)；正式链的时间、信任、事务与恢复矩阵见 [第十四批验收](acceptance-v14.md#验证矩阵)。对应证据继续由 `closed-bar-runtime.test.ts`、`closed-bar-boundaries.test.ts`、`storage-faults.test.ts`、`events-feed.test.ts`、`audit-replay.test.ts`、领域/市场数据测试及浏览器套件覆盖。本增量补充正式运行链性能与测量工具的失败自检，不删改任何历史验收或未完成条件。
