# 采样回执核验

设置抽屉 → 只读行情采样 → 各周期采样进度 → 查看采样回执。这里读取已存档的适配器样本，不调用供应商，也不改变隔离状态。没有记录不能证明无成交、权限正常或采样成功。

## 操作

1. 选择请求周期。每页最多 20 条，按本地收录序号倒序排列。首次读取固定收录上限；读取更早回执不会混入后来收样。点击「重新读取回执」建立新快照。
2. 选择回执，核对供应商时间、适配器接收时间、服务端观测时间、来源、连接批次、隔离原因及哈希结果。
3. 展开当前与前序原文。原文是适配器输出的 `ProviderBarSample` JSON，不是 SDK 网络报文。浏览器以纯文本显示，不执行其中的 HTML。
4. 下载本条核验 JSON，保存当前所选回执、同根前序、哈希结果、字段差异和查询快照。下载使用已显示的报告，不重新读取最新数据。

旧版回执的请求周期显示为「未知」。新记录保存请求周期，即使供应商返回了其他周期，仍保留在原请求范围内。返回周期见原文。迁移不会根据返回周期倒填请求周期。

没有逐周期运行摘要但保有旧接收进度的证券显示「旧版采样存档」。移出当前研究池后仍保留已有运行摘要与存档。接口也可按已知证券 ID 读取保留回执，不要求当前观察列表仍有该证券。

## 校验与比较口径

SHA-256 计算沿用收录时的方法：解析存档对象，排除 `receivedAt`，按保留的字段顺序使用 `JSON.stringify` 序列化，再计算摘要。结果区分一致、不一致、无效 JSON 和超限。它校验样本内容，不覆盖回执元数据，不证明来源权威，也不是供应商签名。

比较对象是收录序号更小、且归属证券、来源、原文证券代码、原文返回周期和供应商时间都相同的最近一条回执。请求周期未知的旧记录也可成为前序。比较不以接收时间或当前最新行情排序，排除 `receivedAt` 字段。相同内容重复接收显示「未变」；其他字段改变显示具体差异。字段顺序改变不算字段内容变化。

当前或前序哈希不能核对时，不生成可信差异。前序原文与元数据中的供应商时间不一致时同样拒绝比较。「没有更早的同根回执」只描述本地存档，不表示历史完整；内容变化不等于供应商已确认修订。序号和连接批次也不能证明行情连续。

单条原文最大读取 64 KiB，超限仍返回元数据与明确状态，原文为 `null`，不截断成貌似完整的文本。比较最多读取两条原文。列表不返回原文。

## 接口与升级

- `GET /api/instruments/:id/provider-receipts?period=1D|1m|5m|unknown` 建立读取快照。
- 后续分页带返回的 `snapshot` 和 `nextBefore`（请求参数名为 `before`）；详情使用 `GET .../provider-receipts/:sequence?period=...&snapshot=...`。
- 所有读取须登录，并设置 `Cache-Control: no-store`。未知参数或非法游标返回 400，范围外回执返回 404，恢复或重置后失效的快照返回 409。快照绑定证券、请求周期、数据集版本和收录上限；它不是授权凭据。
- 数据集版本复用现有恢复时轮换的事件流版本。读取在单次 SQLite 事务内完成，不执行建表、迁移或写入。没有新增导入、确认、放行或删除接口。

结构 v9 添加可空的请求周期及列表/前序查询索引。正常启动沿用迁移前备份；列、索引和版本登记同事务提交。旧原文字节、哈希及不可变触发器保留。格式错误的旧 JSON 不阻止升级，查询时明确报告不可读。

此入口支持历史证据排查。真实 OpenAPI 权限、单位、会话、闭合状态、公司行动、正式标准化与连续性仍需独立核验，`liveEligible=false`。
