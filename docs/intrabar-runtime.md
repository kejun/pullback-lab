# 受能力门控的持久盘中运行链（KEJ-56）

## 交付边界

本批补齐正式盘中路径的实现与隔离契约验收，不代表真实逐笔能力验收完成。Longbridge Node SDK 5.2.0 仍缺少足以证明包级连续性的公开字段，生产 Longbridge 适配器继续强制关闭 `sequenceContractVerified` 和 `continuousTradesVerified`。KEJ-56 必须保持未验收，不能因合成测试通过而设为 Done。

没有新增交易账户、下单、行情购买、密钥读取或行情上传入口。用户必须把计划明确保存为 `INTRABAR_CROSS`，并在正式监测面板再次确认启用；默认模式仍是收盘确认。

## 服务器契约

`ClosedBarContext.tickContract` 只能来自经审计的进程内只读适配器。客户端请求、人工资料、探针回执和本地计数器都不能提供它。仅有 `LIVE_TICK` 两个布尔能力标记仍不足以启用。

本版本刻意只支持一种可审查协议：

- 序号作用域为同一证券、同一会话；连接级全局序号、跨证券过滤后的不完整包流均不支持。
- 每包保留原始 `providerEpoch`、`providerSequence` 和供应商明确提供的 `previousProviderSequence`。非 +1 的序号可以存在，但必须有已审计的供应商前驱链。不得用本地 +1、事件时间排序或“上一收到的包”补造前驱字段。
- `position` 保留供应商定义的包内位置，必须完整连续地从 0 开始。等时刻成交按照此位置处理，时间倒退拒绝，绝不重排。
- `coverageFrom` / `coverageThrough` 必须是供应商协议认证的无缺口覆盖区间，不能从首末成交时间、心跳到达时间或本地时钟推算。初包的前驱必须为空，后包的起点必须等于前包终点。空包仅表示供应商明确认证的无成交覆盖，不制造成交。
- 只接受完整的正常会话普通成交。更正、撤单、非普通成交类型或无法完整解释的过滤语义全部拒绝。
- 审计证据包括协议证据 ID、原始脱敏样本 SHA-256、验证时间和有效期，明确重连必须新代际并人工恢复。

如果真实供应商无法提供上述某一字段或保证，就不能使用这个适配器契约。实现中没有提供生产 tick 适配器，更没有把 Longbridge 报价或 OHLC 转换成符合契约的逐笔包。

## 持久化与因果

SQLite migration 12 新增不可变 `tick_packets` 和 `tick_trades`；完整原始包、接收时间及哈希仍保存在 `closed_receipts`。包索引保留供应商 epoch/sequence，成交表保留原始包内位置和相应 token。原始输入、标准化输入、状态、资金复核、事件、通知及处理结果共享既有事务边界。通知插入失败会回滚包索引、成交与判断，重试后只产生一条入场事件。

连续性预检先检查决策时已接收的整个待处理队列。较晚收到的缺包、冲突、epoch 重置或止损事实会在较早机会提交前阻止行动。重复包相同内容幂等，重复序号不同内容暂停。风险估价使用验证后的唯一包链尾和包内顺序；同毫秒旧包重传不会通过更大的本地接收序号覆盖最新成交。

触碰必须先发生，参考必须最终确认。同一候选内只有 `ref_ready` 之后连续两笔的从阈值下到阈值上的穿越才能触发；分钟高点不会补造顺序。触发后回落追加 `BREAKOUT_FADED`，不撤销原事件。盘中截止不享受收盘 30 秒宽限；迟到成交、已过期证据、过时决策或重启积压都不能追发行动提醒。

连接回调由运行时 epoch 隔离，供应商 epoch 改变会使旧尝试暂停。重启只保留历史，不能恢复积压机会。用户必须显式创建恢复尝试，并重新出现高于支撑区上沿后回踩的证据。正式快照标为 `intrabar-v1`，保留相同的确定性触发与冻结资金风险重放机制。

追涨限制启用时，会话低点必须来自自开盘起完整的认证逐笔覆盖，并覆盖当前风险报价。不能用不完整分钟或局部 tick 流冒充全会话低点。

## 界面与 API

`/api/bootstrap` 仅返回逐证券的 `intrabarEligibleInstrumentIds`，不会把一个标的的验证结果推广为整个市场。监测状态返回 `tickEligible` / `tickReason` 和实际尝试模式。盘中下拉选项、启用和恢复按钮依据精确证券资格门控；服务器在执行时重新验证。UI 展示两种模式差异、盘中回落风险及未开放原因。

没有 tick 输入或能力声明上传 API；在启用请求中附加 `LIVE_TICK`、`verified` 或伪造协议对象不会放行。
