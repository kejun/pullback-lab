# 正式监测控制与读回验收

现有「标的与计划」页在已保存的非演示计划下显示「正式收盘监测」。它读取 `GET /api/plans/:id/monitor` 的逐证券资格，不从演示开关、候选日线、人工历史或客户端字段推导正式能力。生产启动未安装正式适配器时，页面明确显示未配置且启用禁用。

## 状态与控制

显示连接、逐标资格、实际收盘模式、计划版本、尝试身份/版本/会话、来源尝试、激活和输入水位、截止裁决水位、输入数量以及服务端原因码。每五秒在页面可见且没有待确认/失败操作时只读刷新。最近读取时间保留；失败后标为上次读回，暂停所有命令，需显式刷新核对。

启用、暂停、恢复都先展示当前计划/尝试与后果，再显式确认提交。取消只关闭确认，不发送命令。提交同步上锁，避免快速重复点击；命令均带计划版本和当前尝试 CAS，恢复另带来源尝试与精确水位。失败、409、超时不自动重试，不乐观假定已经启用。命令后读回计划和运行进度。

恢复创建新尝试和证据代际。确认前明确说明：旧机会和迟到输入不追发，不代表会话首次，需重新高于支撑区上沿再回踩。人工历史、缺服务端冻结依据、未核验证券与盘中逐笔均不能通过该入口启用。行情断开不会阻止用户显式暂停已有尝试。

`progress.sessionDate` 来自持久冻结上下文，不由客户端推断。较早会话只读展示，新版本指定新会话时可走首次启用；同会话旧尝试不能冒充首次，仍需显式恢复。缺少会话字段的旧响应保守禁用首次/恢复。

组件随计划版本/尝试身份重挂载，读请求有代际与取消隔离。React StrictMode 的 setup-cleanup-setup 释放旧读锁，旧请求的 finally 不能解开新请求的锁。切换证券和页面后，旧响应不能写入新面板。未保存草稿/历史只读图表/并发冲突期间控制禁用，不覆盖用户输入。

## 验证范围

- 门控/命令体单测：逐标资格，未配置/断开，人工资料，缺冻结依据，盘中禁用，既有尝试不可首次，跨版本恢复，终态阻断，失去能力后暂停，最小CAS命令体。
- 生命周期回归：StrictMode取消重挂载、旧读回/旧finally隔离。
- 会话回归：服务端返回冻结旧会话；跨日新计划可首次、同日不能重做、缺会话响应保守阻断。
- 浏览器：隔离 ContractAdapter + 文件SQLite + 实际鉴权与 API；启用/暂停/恢复、取消零写入、双击单提交、真实409冲突、失败后显式刷新、迟到状态切标隔离；桌面和390px截图保留普通滚动与固定导航，测量可见边界与命中区域。
- 既有人工历史浏览器场景验证默认无适配器，且人工资料不能提升资格。

所有行情是离线合成契约夹具。测试代码不由生产启动加载；没有证明上传、客户端verified开关、凭据配置、交易或部署动作。CI的容器smoke不代表目标主机验收。真实OpenAPI权限、生产适配器、最终闭合/完整性、目标主机及真实延迟仍需独立验收。
